# Работа над fmem

Пиши документацию по-русски. Используй методы fstack. У каждого изменяемого файла
должен быть один ответственный исполнитель; проверки можно выполнять параллельно.

Markdown в Obsidian — источник знаний. Поисковый индекс восстанавливаемый,
журнал принятых операций — долговечный. Никогда не сбрасывай их одним действием.
Сохраняй совместимость формата fstack; изменение схемы требует явного перехода.
Не используй действующий vault пользователя для тестов.

До отправки выполни fmt, clippy с запретом предупреждений, release tests для
обычной сборки и `--no-default-features`. Проверяй сетевую загрузку и реальную
модель отдельно. Не допускай загрузок моделей из хуков или обычного поиска.
При изменении зависимости обнови Cargo.lock и уведомления поставляемого бинарника.

Не обещай ускорение без одинакового корпуса, режима и метода измерения.
Сохранение, разрешение записи и retrieval проверяй независимыми сценариями.
