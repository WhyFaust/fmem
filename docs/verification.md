# Проверка локального поиска

Rust 1.90.0 (`1159e78c4`), Linux 6.18.57 x86_64, Intel Xeon Platinum 8573C,
9 логических CPU, доступных процессу. Измерения выполнены в контейнере в
профиле Cargo `test` с отладочной сборкой.

## Лексический поиск

```bash
cargo +1.90.0 test --locked --lib search::tests -- --nocapture
cargo +1.90.0 test --locked --lib --no-default-features search::tests -- --nocapture
cargo +1.90.0 test --locked --lib benchmark_persistent_against_legacy -- --ignored --nocapture
```

Тесты проверяют внешнюю правку и удаление файла, восстановление повреждённого
индекса, русское словоизменение, фильтрацию вида и области перед top‑k, слияние
рангов и отбрасывание эмбеддингов, вычисленных для удалённой или изменённой
ревизии. Библиотека без `local-embeddings` проходит те же проверки.

Бенчмарк создаёт 750 активных Markdown-записей и для трёх запросов сверяет
первые десять идентификаторов и их порядок. Эталон строит SQLite FTS5 в
памяти на каждом запросе, как прежний поиск fstack. Дисковый вариант при
замере холодного старта начинает с пустого кеша и строит индекс перед
запросом. Прогретый вариант повторно открывает существующую БД и сверяет
актуальность Markdown. Медианы и диапазоны получены из девяти запусков на
запрос. Замер холодного старта одиночный.

| Запрос | Эталон, медиана [мин., макс.], мс | Дисковый, холодный старт, мс | Дисковый, прогретый, медиана [мин., макс.], мс |
| --- | ---: | ---: | ---: |
| `pagination boundaries` | 509,5 [491,3, 609,7] | 819,6 | 28,0 [25,4, 40,2] |
| `отправка посылки` | 549,9 [541,3, 605,9] | 792,2 | 26,8 [25,4, 32,7] |
| `schema migration` | 505,6 [492,4, 533,8] | 671,4 | 28,3 [26,5, 35,4] |

Порядок top‑10 совпал во всех замерах. В цифры вошли обход хранилища,
обновления кеша и выборка. ОС не сбрасывала файловый кеш между запусками.
Корпус синтетический. Производительность и ранжирование на другом корпусе
зависят от текста, размера хранилища, файловой системы и состояния кеша.

## Семантический и гибридный поиск

Выполнен тест на CPU с `intfloat/multilingual-e5-small` FP32 ревизии
`614241f622f53c4eeff9890bdc4f31cfecc418b3` и ONNX Runtime 1.22.0.
ONNX-файл весит 470 268 510 байт. Тест запускает локальную модель после
проверки SHA-256 пяти файлов и установки во временный каталог.

```bash
FMEM_TEST_MODEL_SOURCE=/path/to/model-files \
ORT_DYLIB_PATH=/path/to/libonnxruntime.so \
cargo +1.90.0 test --locked --lib multilingual_model_recovers -- --ignored --nocapture
```

`FMEM_TEST_MODEL_SOURCE` указывает на локальную копию файлов из ревизии
модели. Если уже выполнен `fmem model install`, можно вместо исходной папки
задать `FMEM_TEST_MODEL_STATE` с путём к локальному состоянию fmem. Если
ONNX Runtime установлен там же, `ORT_DYLIB_PATH` можно опустить.

| Запрос | Результат top‑1 в semantic и hybrid | Косинусное сходство semantic |
| --- | --- | ---: |
| Как переслать заказ клиенту? | Порядок доставки | 0,838 |
| Where do I book time off work? | Vacation request | 0,846 |

Лексический поиск не вернул совпадений для этих двух запросов на наборе из
четырёх записей. Повторная индексация сохранила готовые векторы. При добавлении
новой записи гибридный режим возвращает лексическое совпадение и сообщает,
что часть записей ждёт семантической индексации. Инкрементальный проход
вычисляет один недостающий вектор.
